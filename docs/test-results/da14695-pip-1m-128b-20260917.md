# DA14695 PIP HRS：1M / 128B / nRF52840DK

日期：2026-09-17

## 测试配置

- 发射端：DA14695，peripheral-side PIP，固定随机地址
  `C0:DE:52:84:00:41`
- 正常 BLE 对端：nRF52840DK HRS central（工程历史名称中的 `52833` 不代表
  本轮硬件）
- PHY：对称 LE 1M；connection interval 20ms；supervision timeout 4s
- 接收端：B210，2420MHz 中心频率，40MS/s，40MHz 带宽，RX2
- 下发：DA UART 的 `phantom pip-covert-hex <hex>`，covert data 不参与
  软件 CRC 或软件 whitening
- 烧写：DA 和 nRF52840DK 均使用固定序列号的命令行烧写/复位，没有交互式窗口

## 结果

同参数无 PIP 对照 `20260917_da_nopip_control_128b_1405` 保持连接，DA 没有
生成 `pip-image`。PIP 运行 `20260917_da_pip_measure_128b_1535` 中：

- nRF52840DK 持续收到有效 HRS notification，`crc_invalid=0`，没有
  `reason=8` supervision timeout；
- DA 记录 `PHANTOM_PIP_ACK len=128` 和 `pdu_len=148 payload_len=146`；
- PIP TX 后 `cur_len=140 → cur_len=0, offset=0, pyld=0`，下一真实 AA
  接收 `rx_crc=1`；
- 参考 USRP 审计记录恢复出完整 128B covert data，逐字节匹配下发值。

## 1M 时序测量

PIP 事件记录：

```text
comp=48 base=46 frame2=1 airtime=1248 prep=234
cost_total=64 cost_fill=38 cost_crc=9 cost_inner=12
cost_fake=2 cost_other=3
RX_END=6586192 PHY_TO_IDLE=6586214 TX_PREP_DONE=6586223
TX_START=6586491 TX_END=6587622
```

普通 RX→TX 响应的 `RX_END→TX_START` 约为 143us；本次 PIP 为 299us。当前
1M `comp=48us` 已使 `CM_FRAME_2` 偏移达到 1us 下限，继续增大不会进一步
提前。若要求 PIP 严格落在 150us TIFS 内，需要把 PIP image 准备前移或减少
约 149us 的调度延迟；不能只继续增大 48us 补偿值。

原始 IQ 和完整 UART 日志不纳入公开仓库，保留在外层 `test/` 的对应 run
目录中。
