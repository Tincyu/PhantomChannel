# DA14695 PIP HRS：1M / 128B / nRF52840DK

日期：2026-09-17

## 测试配置

- 发射端：DA14695，peripheral-side PIP，固定随机地址
  `C0:DE:52:84:00:41`
- 正常 BLE 对端：nRF52840DK HRS central（工程历史名称中的 `52833` 不代表
  本轮硬件）
- PHY：对称 LE 1M；connection interval 20ms；supervision timeout 4s
- 接收端：B210，2420MHz 中心频率，40MS/s，40MHz 带宽，RX2
- 下发：DA UART 的 `phantom pip-covert-hex <hex>`，covert data 不参与
  软件 CRC 或软件 whitening
- 烧写：DA 和 nRF52840DK 均使用固定序列号的命令行烧写/复位，没有交互式窗口

生成 `pip-image`。PIP 运行 `20260917_da_pip_measure_128b_1535` 中：

- nRF52840DK 持续收到有效 HRS notification，`crc_invalid=0`，没有
  `reason=8` supervision timeout；
- DA 记录 `PHANTOM_PIP_ACK len=128` 和 `pdu_len=148 payload_len=146`；
- PIP TX 后 `cur_len=140 → cur_len=0, offset=0, pyld=0`，下一真实 AA

- 参考 USRP 审计记录恢复出完整 128B covert data，逐字节匹配下发值。

## 1M 时序测量

PIP 事件记录：

```text
comp=48 base=46 frame2=1 airtime=1248 prep=234
cost_total=64 cost_fill=38 cost_crc=9 cost_inner=12
cost_fake=2 cost_other=3
RX_END=6586192 PHY_TO_IDLE=6586214 TX_PREP_DONE=6586223
TX_START=6586491 TX_END=6587622
```

普通 RX→TX 响应的 `RX_END→TX_START` 约为 143us；本次 PIP 为 299us。当前
1M `comp=48us` 已使 `CM_FRAME_2` 偏移达到 1us 下限，继续增大不会进一步
提前。若要求 PIP 严格落在 150us TIFS 内，需要把 PIP image 准备前移或减少
约 149us 的调度延迟；不能只继续增大 48us 补偿值。

原始 IQ 和完整 UART 日志不纳入公开仓库，保留在外层 `test/` 的对应 run
目录中。

## 队列释放修复与 RX-start 实验审计

此前 128B supervision timeout 的直接原因是 fake-AA PIP 发出后，DA 的
`cur_tx_pdu` 没有在 TX_DONE 路径释放，`txinfo.offset` 也没有清零；下一连接
事件会重复取同一 PDU 并继续发 fake-AA，52840DK 因而无法返回正常 BLE ACK，
最终耗尽 supervision timeout。修复后在 PIP TX_DONE 中一次性释放该节点、清零
`offset/pyld_len`，并等待下一次真实 AA RX/NESN。

为验证更早的 frame2 接管，曾运行
`20260917_da_pip_earlyfields_ackempty_128b_2020`。该实验只有软件侧
`PHANTOM_PIP_TX` 快照，没有 `cmac pip-image`/`cmac pip-timing` 或 TX_DONE；
52840DK 只收到 4 个 notification，随后 `reason=8` 断开。因此该路径判为无效，
不能作为空口 PIP 已发出或 USRP 已恢复的证据。

正式稳定镜像 1.0.14 将实验开关
`BLE_PHY_COVERT_PIP_EARLY_ENABLE` 置为 `0`，保留 enqueue-time 预构建和
TX_DONE 释放修复。复测
`20260917_da_pip_stable_prebuild_128b_1940` 中只出现一次 128B PIP，随后
`cur_len=140 → cur_len=0, offset=0, pyld=0`，下一事件 `rx_crc=1`，
52840DK 在测试窗口内持续连接。B210 完成 200M samples 但有 1 次 overflow，
因此采集程序返回 2；IQ 已保留，不能将该采集告警当作 BLE 断链。

当前状态：128B 的连接稳定性和同链路完整 covert data 恢复已有证据；PIP
仍有约 149us 的 image 准备/调度延迟，RX-start 提前路径需要单独重做 PHY
状态机交接，尚未宣称严格 TIFS 内的时序优化或完成更长长度矩阵验收。

## 64B 再复跑

镜像 1.0.14 重新通过固定 DA J-Link 序列号命令行非交互式刷写后，使用相同
的 1M/52840DK/B210 配置复跑。第一次目录
`20260917_da_pip_stable_prebuild_64b_1957` 因连接观察窗口结束时命令未发送，
判为无效，不计入结果。

有效目录 `20260917_da_pip_stable_prebuild_64b_195955` 的证据为：

- DA 收到 64B 动态下发并记录 `PHANTOM_PIP_ACK len=64`；
- 只出现一次 `PHANTOM_PIP_TX len=64`，TX_DONE 后 `cur_len=76 → 0`、
  `offset=0`，下一事件为 real-AA `rx_crc=1`；
- 52840DK 在 30s 窗口内保持连接，收到 33 条有效 HRS notification，无
  supervision timeout；
- USRP 使用 `da14695_sw_fake_header_only_no_hw` 合同恢复 1 条 `ok`，
  `covert_len=64`，恢复字节与下发值完全一致；
- B210 完成 1.2G samples，但有 5 次 overflow；IQ 已保留，采集程序状态为
  `completed_with_errors`，不影响本次恢复记录。
